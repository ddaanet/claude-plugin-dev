## Open decisions

- Whether to trust the deleted brief audit's finding that `docs/changelog/2026-08-14-dist-ref-stops-squash-leak.md` is wrong to call the bootstrap gap "narrowed but not closed". Its evidence survives nowhere else: the whole `dist-` lineage carries no gitlink in any commit, so a `dist-v*` fetch has nothing for `fetch.recurseSubmodules=on-demand` to recurse into; and no pre-0.5.2 recipe refuses a `dist-` ref — `git show v0.4.0:release.just` through `v0.5.1:release.just` all carry a `case` with arms for `v*` and `main|master|HEAD` and no default, so `dist-v0.6.0` falls through to the pull. Claimed verified on a `$TMPDIR` fixture: a consumer vendored at source tag `v0.5.3` (so `plugin-dev/memory` is a `160000` in its index) pulled with the unscoped pre-0.5.2 command `git subtree pull --prefix=plugin-dev <repo> dist-v0.6.0 --squash` exits 0 and deletes `plugin-dev/memory` along with the rest of the leaked environment. Never reproduced independently. A dated entry is never revised, so confirming it means a new dated entry, not an edit.
- The install/update invocation design, interrupted mid-brainstorm. Three separable questions: (a) should `install.sh` default its ref to the newest `dist-` tag resolved from the remote, removing the version argument entirely; (b) should the docs point at `../claude-plugin-dev/toolkit/install.sh` on the assumption of a sibling checkout, replacing the clone-to-`/tmp` step; (c) should a separate `update.sh` own consumer-side migrations — the class the per-release briefs describe by hand, e.g. v0.4.0 requiring a `prerelease` recipe before the subtree lands. Key finding: `install.sh` fetches from `TOOLKIT_URL`, not from the checkout it runs out of, so (b) needs no code change — only (a) and (c) do. Classified bounded for (a)/(b), architectural for (c).
- The ddaanet memory tier divergence. This repo's root `memory/MEMORY.md` block is older than `memory/ddaanet`'s local HEAD, whose newer content sits in unpushed tier commits. Composition mirrors root to tier, so every commit here rewrites five index lines back to their 2026-08-01 wording and would publish that regression to the shared tier. `/gitlore:merge` is a no-op — both stores match their remotes. Either propagate tier to root (reopening the index-budget question below) or keep restoring `memory/ddaanet/MEMORY.md` by hand after each gate run.
- Which index pointers to retire for the ~24.4KB loader cap (root is ~24.7KB, so its tail is silently dropped in every ddaanet repo). The remedy is fixed — retire a pointer, never shorten one into an unroutable line — but the selection is unmade. Separately, four root pointers name targets absent from the store and need dropping or redirecting: `shell-gotchas-on-review`, `skill-vs-command`, `verify-session-root`, `run-the-gate-not-a-suite-subset`.
- Whether the five consumers already at `dist-v0.6.0` need a docs-only re-pull for the README fix, or whether it rides their next routine update.
