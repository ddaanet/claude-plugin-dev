# Migrating to 0.16.0 (breaking)

0.16.0 adds a mode check, `check-modes.sh`, and a `check-modes` recipe in
`release.just` that wraps it. It refuses a vendored script that starts with `#!`
but lacks the execute bit, a flip a consumer commit can make after vendoring.
`install.sh`, `update.sh`, `version-guard.sh` and `exempt-list.sh` are now
executable like every other shipped script that starts with `#!`. The manual
section is [Mode check](../README.md#mode-check).

**Nothing applies with no step taken.** `update.sh` edits nothing outside
`plugin-dev/`, and nothing in the release flow calls `check-modes`: a plugin
that takes no step below is unaffected, unless its own justfile already defines
a `check-modes` recipe, which step 0 repairs. The other steps adopt the check.

## 0. Rename a recipe of your own named `check-modes`

`just` refuses a recipe defined in both an import and the importer. If your
justfile already defines `check-modes`, the pull has broken it: every `just`
command now fails with ``error: Recipe `check-modes` first defined on line …``.
Rename yours (to `modes-check`, say) and update whatever calls it, then confirm
the justfile compiles.

```sh
just --list
```

## 1. Wire it into `precommit`

Nothing wires it for you. Add it by hand beside the other checks:

```just
precommit: check-refs check-size check-frontmatter check-modes
```

Confirm with `just --dry-run precommit` that the dependency is listed.

## 2. Run it once

```sh
just check-modes
```

Each file that starts with `#!` and is not executable is one line,
`mode-lost: <path>`, followed by a `chmod +x` command over the same files by
absolute path. Run that command from anywhere, then commit the mode change. A
pass prints `check-modes: <n> #! files checked, all executable`.
