# Migrating to 0.9.0

0.9.0 ships a `claude` shim at `plugin-dev/bin/claude` that loads the plugin
from a synced copy in `dist/plugin/`, plus `just dogfood` to re-sync it. Run
these steps from the plugin's root, in order. Each one is a no-op where it
already holds.

1. Re-run the installer, from your own shell rather than an agent's sandboxed
   Bash, which refuses writes to `.claude/settings.json`:

   ```sh
   bash plugin-dev/install.sh
   ```

   It adds the dogfood `PreToolUse` and `SessionStart` hooks, and
   `update-plugin-dev` does not re-run it.

2. Remove any hand-copied `.bin/claude` shim, since the vendored one replaces
   it:

   ```sh
   git rm --ignore-unmatch .bin/claude
   grep -n '\.bin' .envrc justfile
   ```

   Delete the `PATH_add .bin` line in `.envrc` and its comment, and any
   `justfile` line naming `.bin/claude`: a `precommit` that shellchecks it fails
   once the file is gone.

3. Put the shim on PATH as the last `PATH_add` in `.envrc`, after
   `PATH_add .gitlore/bin`, so it is the `claude` found first:

   ```sh
   PATH_add plugin-dev/bin
   ```

   Then run `direnv allow`.

4. Ignore the copy, since the sync refuses to run until git ignores it:

   ```sh
   git check-ignore -q dist/plugin/ || printf '\n/dist/plugin/\n' >> .gitignore
   ```

   If a `clean` recipe deletes `dist/`, make it spare `dist/plugin/`: a live
   session loads its skills and hooks from there.
